# AI 聊天室（`.ai/chat/`）

2～4 個 AI（ClaudeCode／Codex／OpenCode／GeminiCLI）各帶一個角色，針對使用者給的主題
**輪流**討論，最後由主持人寫結論。搬移自舊版 v1.2.8 的
`MainWindow.ChatRoom.cs`、`Services/ChatRoom/ChatRoleLibrary.cs`、`Resources/ChatRoom/`。

**和代理團隊的關係**：畫面、分頁、沙盒、啟動、停止、恢復**全部沿用**同一套
（`docs/MULTI-AGENT.md`）。唯一的差別是溝通方式——代理團隊走 `.ai/bus/` 信箱互寄信，
聊天室由 AwayTerminal 主持：輪到誰就在那一格打一行字，它把發言寫成檔案，
AwayTerminal 接進共用紀錄，再換下一位。

---

## 1. 建聊天室視窗

「新分頁 ▾ → AI聊天室…」→ 先選資料夾 → 設定視窗 → 開好之後**問主題**（可以取消，
之後右鍵「開始討論…」再給）。

視窗和代理團隊是**同一個**，只是換了幾個欄位（舊版也是同一個 `MultiAgentDialog`）：

| 欄位 | 代理團隊 | AI 聊天室 |
|---|---|---|
| 第一列 | 投遞限制次數（10／30／50／100／不限） | **討論回合**（3／5／8／10，預設 3） |
| 第二列 | 閒置檢查 | **整列隱藏**（聊天室不投遞信） |
| 沙盒 | 勾選，預設關（2026-10-02 起；原本預設開） | 同 |
| 每格欄位名 | 代理人類型／代理人角色 | **使用的 AI／角色** |
| 第 1 位的角色 | 使用者選（預設 PM） | **固定主持人**，下拉停用 |
| 角色清單 | 5 個（`multiagent/roles/`） | **21 個**（`chatroom/roles/`） |
| 最少幾位 | 1（格 1 一定啟用） | **2**（少於兩位討論不起來） |

## 2. `.ai/chat/` 的檔案格式

```text
<工作區>/.ai/chat/<yyyyMMdd-HHmm>[-n]/
    transcript.md        ← 共用紀錄，**只有 AwayTerminal 寫**
    r{回合}-Agent-xx.md  ← 每個人自己這一輪的發言（300 字以內）
    conclusion.md        ← 主持人最後寫的結論（600 字以內）
```

- **一場討論一個資料夾**，名字是開始討論時的時間。同一分鐘內又開一場（同資料夾兩間聊天室、
  連續換主題）就補 `-2`、`-3`，**不共用**。
- 換主題時如果這個資料夾已經有 `transcript.md` → **開新的資料夾**，上一場的發言檔與結論
  原封不動留在舊資料夾。
- 誰寫誰讀：**agent 只寫自己那一個檔**；`transcript.md` 由 AwayTerminal 追加，
  `common.md` 明文禁止 agent 改它或改別人的發言檔。
- `.ai/` 已經在 `.gitignore` 裡（和信箱同一條，見 `bus::ensure_gitignore`）。

**沒有 watcher**：代理團隊要「發現任何人隨時寫的信」所以要掃目錄；聊天室是**我們先開口問**，
然後只等那一個檔案，所以 600ms 的 tick 直接看那個檔的 mtime 就夠。舊版也是這樣。

### 讀「寫完了」的判斷（`read_finished`，兩個條件都照舊版）

1. mtime **不能早於**我們開口問的時間 −2 秒
   （FAT／網路磁碟的 mtime 只有 2 秒解析度，留餘裕）
2. mtime 至少 1 秒前（還在寫的檔不要讀）

第 1 條是**必要**的：恢復分頁或同一個資料夾再開一場時，上一場留下的 `r1-Agent-11.md`
會被當成這一場的發言。

## 3. 發言機制

| 事 | 規則 |
|---|---|
| 誰先說 | **依格號**（第 1 位＝主持人），一回合裡每人各一次 |
| 下一個怎麼決定 | 輪流，不是主持人指定 |
| 什麼時候打字進去 | **和代理團隊同一個 `agent_ready`**（6 個條件；見 `docs/MULTI-AGENT.md` 第 5 節） |
| 打什麼 | `[AwayTerminal] 第 {n}/{N} 回合，輪到你（{角色}）發言：請先讀 {transcript} …再把你的發言寫進 {檔案}（300 字以內，UTF-8）…` |
| 收到發言之後 | 接進 `transcript.md`（標題 `## 第 n 回合 · Agent-xx（角色）`），換下一位 |
| 某位沒回應 | **5 分鐘**逾時 → 跳過並在紀錄註明；「一直忙碌連問都問不到」也算（從輪到他開始算） |
| 某格已結束 | **不等 5 分鐘**，直接跳過並註明 |
| 等發言期間名單變了 | 一律用 **Agent ID** 找回他，不是靠索引（否則最後一位那一輪會被整個略過） |
| 使用者插話 | 右鍵「插話…」→ 接進 `transcript.md`（`## 使用者`），**下一位就看得到**。只有討論中／寫結論中能插 |
| 結束條件 | 回合數跑完，或右鍵「結束討論」（這一輪結束後就去寫結論，不再多問一個人） |
| 結論 | 只問**主持人**：讀完整份紀錄 → 寫 `conclusion.md` → 接進紀錄 → 狀態變成已結束。逾時 **10 分鐘**（兩倍） |
| 主持人已結束 | 沒人能寫結論 → 在紀錄註明並收場 |

階段機：`等主題 → 討論中 → 寫結論 → 已結束`。

## 4. 21 個角色

原樣照舊版 `Resources/ChatRoom/`，**不翻譯**（那是給 agent 讀的，和代理團隊的角色檔同一條
規則）。下拉順序照舊版 `ChatRoleLibrary.BuiltInRoles`：

主持人、反方辯論者、情報研究員、軟體工程師、嵌入式工程師、射頻工程師、無線通訊專家、
硬體工程師、網路工程師、雲端工程師、安全專家、法律顧問、投資分析師、行銷專家、
健康顧問、教育顧問、職涯顧問、心理顧問、旅遊規劃師、創意設計師、感情顧問。

第 1～4 位的預設：主持人、反方辯論者、情報研究員、軟體工程師。

角色檔是三層（同代理團隊）：`common.md` ＋ `roles/<角色>.md` ＋ **執行期脈絡**。
聊天室的執行期脈絡和代理團隊的**完全不同，而且是中文**（照舊版）：代號、角色、用的 AI、
聊天室編號、專案資料夾、回合數、參加者名單、主持人是誰、討論紀錄與自己發言檔的路徑、
「路徑一律以打進來那一行為準」、主持人多一段「你要寫結論」、最後是這次的主題。

範本第一次用到時複製到 `<設定資料夾>/chatroom/`，自動更新機制和代理團隊共用同一套
（`.defaults.json` 的正規化 SHA-256；使用者改過的不動）。

## 5. 和代理團隊共用／不同

**共用**（同一份程式，聊天室只是另一種 group kind）：

- `Team`／`Slot`（`kind` 欄位決定是哪一種）、pane 排版與 `g`／`u`／`E`／`G` 四條協定
- 分頁列一組一列、點那一列一律回到第 1 格（2.1.2 起）、關閉整組要確認
- 沙盒（**一間聊天室一棵 worktree**）、Job Object、護欄
- 啟動那條路（`session_create(kind="agent")`）、四家 CLI 的角色注入方式
- `agent_ready`（6 個閘門）、`send_text_then_enter`（文字＋300ms 後 Enter）、Enter 補送
- 停止任務（Esc → Ctrl+U → 停止句）
- 恢復分頁（`SavedTab` 的 `agent*` 欄位，多一個 `agentKind`／`agentRounds`／`agentChatFolder`）
- 改名（`agent_team_rename`）
- 角色庫的實作（`roles.rs` 的 `Library`：`TEAM` 與 `CHAT` 兩個常數）

**不同**：

| 項目 | 代理團隊 | AI 聊天室 |
|---|---|---|
| 溝通 | `.ai/bus/` 信箱，agent 之間互寄 | `.ai/chat/<資料夾>/`，AwayTerminal 主持 |
| 偵測 | 掃目錄（3 秒）＋穩定 1.5 秒 | 只看「我們問的那一個檔」的 mtime |
| 節流 | 投遞上限 ＋ 暫停／恢復 | **沒有**（改成回合數上限） |
| 閒置檢查 | 有（請 Agent-x1 問大家） | **沒有** |
| 執行期脈絡 | 英文，講信箱與回報規則 | 中文，講發言檔與輪流規則 |
| 第 1 位 | PM（可改） | **主持人（固定）** |
| 角色庫 | `multiagent/`，5 個角色 | `chatroom/`，21 個角色 |
| 最少人數 | 1 | 2 |
| 恢復之後 | 佇列與 `.delivered` 都還在，接著跑 | **進度不回來**，停在「等主題」（CLI 都是新 session） |

## 6. UI 呈現

- 分頁列**一組一列**（同代理團隊）；那一列的小標記顯示「人數·第 n/N 回合」
  （等主題／寫結論／已結束時只顯示人數）。
- tooltip 第一行是進度：`等你給討論主題（右鍵「開始討論…」）`／`討論中 第 2/3 回合`／
  `主持人正在寫結論`／`討論已結束（右鍵可開啟討論紀錄資料夾）`。
- pane 排版和代理團隊一樣「下一上 N−1」：**下方全寬那格＝主持人**，上列是其他參加者。
  外框顏色照格號（1 淡紅、2 淡藍、3 淡綠、4 淡紫）。
- 右鍵選單（聊天室那一列）：AI聊天室設定…／開始討論／換主題…／插話…／結束討論／
  開啟討論紀錄資料夾／更改名稱／關閉。「插話」在還沒開始或已結束時是灰的，
  「結束討論」只有討論中才亮。

## 刻意與舊版不同

| 項目 | 舊版 | 這裡 | 為什麼 |
|---|---|---|---|
| 主題／插話的輸入框 | WPF `InputDialog(multiline: true)`，Enter 換行、按「確定」送出 | 頁內 `<textarea>`，**Ctrl+Enter 送出** | 頁內對話框沒有預設按鈕的概念，多行輸入又不能把 Enter 當送出 |
| 兩個角色庫 | `RoleLibrary` 與 `ChatRoleLibrary` 兩個類別（雜湊機制、三層組合、標題取法各寫一遍） | 一份實作 ＋ `Library` 兩個常數 | 那兩個類別除了資料夾名、範本、角色順序、標題後備之外一模一樣 |
| 分頁列那一列的資訊 | 只有 tooltip | 多一個小標記（人數·回合） | 同代理團隊的作法 |

## 怎麼驗

```bash
cargo test --lib agent::chat            # 檔名／輪替／結論時機／read_finished／資料夾不撞名
cargo build --example fake_agent
cargo run   --example chat_probe        # 三人 × 2 回合 ＋ 插話 ＋ 結論，全程在 %TEMP%
npm run verify                          # --verify 的最後一段是聊天室（假 agent）
```

`chat_probe` 與 `--verify` 都**不啟動真的 claude／codex**、**不碰使用者的 `.ai/`**
（專案在 `%TEMP%`，而且 TASK-019 起**每一段一個子資料夾**）。
